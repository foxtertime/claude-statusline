# claude-statusline

[![CI](https://github.com/foxtertime/claude-statusline/actions/workflows/ci.yml/badge.svg)](https://github.com/foxtertime/claude-statusline/actions/workflows/ci.yml)

Статуслайн для [Claude Code](https://claude.com/claude-code): директория, git-ветка со статусом, модель с размером контекста и уровнем effort, шкала заполнения контекста и лимиты использования с временем сброса.

```
~/projects/app │ main +2 ~1 ?3 ↑1 ≡1 #42 approved │ fix(api): retry on 429 · 2 hours ago
Opus 5 (1M) (high) │ Ctx ━━────────────────── 12% (125K / 1M) │ 38 мин · +156 −23 │ Cache 91% · 19:30
Current ━━━━━─────────────── 24%  02:40
Weekly  ━━━━━━━━──────────── 41%  4 сен, 12:00
```

Всё, кроме директории и модели, появляется только при наличии данных, [скрывается по отдельности](#настройка) и ужимается под ширину терминала.

Что показывается:

- **Строка 1** — текущая директория — ссылкой `file://`, которая открывает её в файловом менеджере или редакторе; git-ветка (или короткий хеш в detached HEAD) — ссылкой на ветку на GitHub либо на репозиторий на другом хостинге — с индикаторами: конфликты (`!`), staged (`+`), modified (`~`), untracked (`?`), ahead/behind (`↑`/`↓`), stash (`≡`), имя git worktree (`wt:имя`), открытый pull request ветки с состоянием ревью (`#123 approved`, для GitLab — `!123`) — ссылкой, если терминал их поддерживает, — тема и возраст последнего коммита. Чистое дерево — `[clean]`, вне репозитория — `[no git]`.
- **Строка 2** — модель, размер контекстного окна, уровень effort, отметка `fast` в быстром режиме и `@имя` агента; шкала заполнения контекста с процентом и токенами; сессия: оценка стоимости, длительность и число добавленных и удалённых строк (`$1.24 · 38 мин · +156 −23`). Стоимость — оценка Claude Code по прайс-листу, а не счёт; по подписке она не показывается. В конце — состояние кэша промпта: `Cache 91% · 19:30` — доля чтений из кэша и время, когда он остынет, или `Cache cold`, если следующий запрос будет прочитан заново целиком. Последними идут режим vim (`NORMAL` / `INSERT`) и имя сессии.
- **Строки 3+** — лимиты использования, по строке на каждое окно, которое передаёт Claude Code:
  - `Current` — 5-часовое окно, `Weekly` — недельное (подписки Pro, Max и Ultra);
  - `Spend` — лимит расходов за шлюзом Claude apps, с суммами в долларах, если шлюз их сообщает.

  Время сброса — в 24-часовом формате: «19:30», если сегодня, иначе «10 мар, 19:30» (в английском варианте — «Mar 10, 19:30»).

Шкалы зелёные до 50 %, жёлтые до 80 %, дальше красные — пороги [настраиваются](#настройка).

Статуслайн подстраивается под ширину терминала. Если строка 1 не помещается, из неё по очереди убираются тема последнего коммита, начало пути (`…/proj/app`, затем `…/app`), хвост имени ветки (`feature/lo…`), затем worktree и pull request и, наконец, стрелки и stash. Строка 2 теряет сегменты с конца, а затем у модели — агента, `fast` и effort. Строки лимитов теряют суммы, время сброса и в последнюю очередь укорачивают шкалу. Иероглифы и эмодзи считаются за две колонки. На терминале уже ~40 колонок самый короткий вариант может всё равно не поместиться — тогда строку обрежет сам Claude Code.

Блоки появляются по мере того, как Claude Code присылает данные: шкала контекста и лимиты — после первого ответа API в сессии.

## Установка

Без клонирования — скачать установщик из последнего релиза, посмотреть и запустить:

```bash
curl -fsSLO https://github.com/foxtertime/claude-statusline/releases/latest/download/install.sh
less install.sh
bash install.sh
```

Установщик скачает `statusline.sh` из того же релиза и сверит его с `SHA256SUMS`; при несовпадении ничего не устанавливается. Конкретную версию можно выбрать так: `STATUSLINE_RELEASE=v1.3.0 bash install.sh`. Так можно ставить начиная с версии 1.3.0 — в более ранних релизах нет нужных файлов.

Из копии репозитория:

```bash
git clone https://github.com/foxtertime/claude-statusline.git
cd claude-statusline && make install    # или: src/install.sh
```

В копии репозитория (её установщик узнаёт по `src/statusline.sh` и `tests/run.sh`) ставится её `src/statusline.sh`; вне её скрипт всегда скачивается и сверяется, даже если рядом с установщиком есть другой `statusline.sh`.

Установщик кладёт скрипт в `~/.claude/statusline.sh` и добавляет в `~/.claude/settings.json`:

```json
"statusLine": { "type": "command", "command": "~/.claude/statusline.sh" }
```

Остальные настройки не затрагиваются, включая соседние поля `statusLine` (`padding`, `refreshInterval`); версия перед последним запуском сохраняется в `settings.json.bak`, а файл, каким он был до первого запуска установщика, — в `settings.json.orig` (он не перезаписывается). Если задана переменная `CLAUDE_CONFIG_DIR`, установка идёт в неё.

Обновление: `git pull && make install` в копии репозитория или повторный запуск скачанного установщика.

Установщик же задаёт [настройки](#настройка), чтобы не править `settings.json` руками. Примеры ниже — для копии репозитория; скачанный установщик запускается так же: `bash install.sh --set …`.

```bash
src/install.sh --set STATUSLINE_LANG=ru --set STATUSLINE_HIDE=commit,spend   # опции
src/install.sh --unset STATUSLINE_HIDE                                       # убрать опцию
src/install.sh --refresh 60                                                  # statusLine.refreshInterval; 0 — убрать
src/install.sh --padding 2                                                   # statusLine.padding; 0 — убрать
```

Опции записываются в блок `env` и применяются после перезапуска Claude Code. Повторная установка их сохраняет. `STATUSLINE_PADDING` установщик всегда выставляет сам по `statusLine.padding`.

Проверить установку — версии `jq` и `git`, `settings.json`, путь к скрипту, пробный запуск, опции:

```bash
src/install.sh --check
```

Удаление — скрипт, ключ `statusLine` и все опции `STATUSLINE_*`:

```bash
src/install.sh --uninstall    # или: make uninstall
```

## Настройка

Статуслайн настраивается переменными окружения. Задать их можно в блоке `env` файла `~/.claude/settings.json`:

```json
"env": { "STATUSLINE_LANG": "en", "STATUSLINE_HIDE": "commit,spend" }
```

или прямо в команде: `"command": "STATUSLINE_LANG=en ~/.claude/statusline.sh"`.

Переменные из блока `env` применяются при запуске Claude Code — после правки перезапустите сессию. Проверено на Claude Code 2.1.327. Учтите, что блок `env` действует на всю сессию, включая команды, которые запускает Claude; если это нежелательно, используйте вариант с командой.

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `STATUSLINE_LANG` | по локали | Язык подписей, дат и единиц времени: `ru` или `en`. Без неё — русский при русской локали (`LC_ALL`, `LC_TIME`, `LANG`), иначе английский |
| `STATUSLINE_BAR_WIDTH` | `20` | Ширина шкал в символах, от 5 до 60 |
| `STATUSLINE_WARN` | `50` | Процент, с которого шкала жёлтая |
| `STATUSLINE_CRIT` | `80` | Процент, с которого шкала красная |
| `STATUSLINE_HIDE` | — | Список скрываемых сегментов через запятую |
| `STATUSLINE_RESET` | `absolute` | Время сброса лимита: `absolute` — «19:30», `relative` — «через 2 ч 10 мин» |
| `STATUSLINE_GIT_CACHE` | `0` | Сколько секунд переиспользовать состояние git; `0` — запрашивать каждый раз |
| `STATUSLINE_LAYOUT` | — | Раскладка строки 2 — см. [ниже](#раскладка) |
| `STATUSLINE_PADDING` | `0` | То же значение, что `statusLine.padding` в `settings.json`. Claude Code не передаёт его скрипту, а оно сужает строку на 2 колонки за единицу — без этой переменной строки с отступом будут обрезаться |
| `STATUSLINE_THEME` | `dark` | `light` — для светлого фона терминала: приглушённый и основной текст становятся тёмными |
| `STATUSLINE_COLOR_<РОЛЬ>` | — | Цвет одной роли в виде кода SGR, например `1;34` (жирный синий) или `38;5;208` (256 цветов); роли — в таблице ниже |
| `STATUSLINE_ASCII` | — | `1` — рисовать только ASCII-символами: шкалы `###---`, разделитель `\|`, `^`/`v` вместо стрелок, `...` вместо многоточия. Для терминалов и шрифтов без псевдографики |
| [`NO_COLOR`](https://no-color.org) | — | Любое непустое значение отключает цвета и ссылки |

Сегменты для `STATUSLINE_HIDE`:

| Сегмент | Что скрывает |
| --- | --- |
| `git` | весь git-блок |
| `commit` | тему и возраст последнего коммита |
| `pr` | pull request текущей ветки |
| `links` | кликабельные ссылки (OSC 8) — директория, ветка, pull request; текст остаётся |
| `worktree` | имя git worktree |
| `effort` | уровень effort |
| `fast` | отметку быстрого режима |
| `agent` | имя агента |
| `context` | шкалу контекста |
| `tokens` | счётчик токенов рядом со шкалой |
| `cost` | стоимость, длительность и строки сессии |
| `cache` | состояние кэша промпта |
| `vim` | режим vim |
| `session` | имя сессии |
| `limits` | все строки лимитов |
| `current`, `weekly`, `spend` | отдельную строку лимита |

### Раскладка

`STATUSLINE_LAYOUT` задаёт порядок сегментов строки 2 после модели: `context`, `cost`, `cache`, `vim`, `session`. Порядок заодно определяет, какие сегменты пропадут первыми на узком терминале — те, что в конце. `/` переносит следующие сегменты на отдельную строку перед лимитами. Не названные сегменты встают в конец последней строки в обычном порядке, неизвестные имена игнорируются; скрываются сегменты по-прежнему через `STATUSLINE_HIDE`.

```bash
STATUSLINE_LAYOUT="cache,context"                    # кэш перед контекстом
STATUSLINE_LAYOUT="context,cost/cache,vim,session"   # кэш, vim и сессия — третьей строкой
STATUSLINE_LAYOUT=compact                            # всё главное в одну строку
```

`compact` выводит одну строку: последний компонент пути, ветку и состояние рабочего дерева, модель с effort, процент контекста и проценты лимитов:

```
…/app │ feature/auth +2 ~1 ?3 │ Opus 5.5 (1M) (high) │ Ctx 62% │ 5h 34% │ 7d 71%
```

Роли для `STATUSLINE_COLOR_<РОЛЬ>`:

| Роль | Что окрашивает | По умолчанию |
| --- | --- | --- |
| `DIR` | директорию | `1;36` |
| `MUTED` | подписи, разделители, второстепенный текст | `2;37` (`90` в светлой теме) |
| `MODEL` | модель | `1;35` |
| `TEXT` | процент контекста, стоимость | `37` (`30` в светлой теме) |
| `OK` | шкалы ниже порога, чистая ветка, staged | `32` |
| `WARN` | шкалы выше `STATUSLINE_WARN`, изменённая ветка | `33` |
| `CRIT` | шкалы выше `STATUSLINE_CRIT`, конфликты, отставание | `31` |
| `ACCENT` | опережение, агент, PR без состояния | `1;36` |

Для ветки и отметок режимов к `OK`, `WARN` и `CRIT` автоматически добавляется жирность (`1;`).

Некорректное значение игнорируется — используется значение по умолчанию.

Посмотреть, как выглядят все сегменты с текущими настройками, не дожидаясь нужного состояния сессии:

```bash
~/.claude/statusline.sh --demo
STATUSLINE_LANG=en STATUSLINE_HIDE=session COLUMNS=100 ~/.claude/statusline.sh --demo
```

Демо берёт данные из встроенного примера и не обращается к git.

Claude Code перерисовывает статуслайн после сообщений, а не по таймеру, поэтому с `STATUSLINE_RESET=relative` оставшееся время устаревает, пока сессия простаивает. Чтобы оно обновлялось, задайте интервал в секундах рядом с командой:

```json
"statusLine": { "type": "command", "command": "~/.claude/statusline.sh", "refreshInterval": 60 }
```

Установщик это поле не добавляет, но и не удаляет при обновлении.

`STATUSLINE_GIT_CACHE` нужен только в очень больших репозиториях, где `git status` заметно тормозит статуслайн: в репозитории на 150 тысяч файлов отрисовка занимает около 100 мс без кэша и 10–20 мс с ним, в обычном — 15 мс и без кэша. Пока запись свежая, изменения в рабочем дереве в статуслайне не видны, поэтому значение стоит держать небольшим, например `5`. Кэш хранится по сессиям в `~/.cache/claude-statusline` (или в `$XDG_CACHE_HOME`).

Режим vim Claude Code показывает и сам — строкой `-- INSERT --` под полем ввода. Чтобы он не дублировался, добавьте в `statusLine` поле `"hideVimModeIndicator": true` либо скройте сегмент: `STATUSLINE_HIDE=vim`.

## Зависимости

- Обязательно: `bash` 3.2+, [`jq`](https://jqlang.org)
- Опционально: `git` 2.15+ — без него не отображается git-блок (счётчик stash требует git 2.35+)

Работает на Linux и macOS (GNU и BSD `date`).

## Проверка

Установленная версия:

```bash
~/.claude/statusline.sh --version
```

Запуск вручную на тестовых данных:

```bash
echo '{"model":{"display_name":"Opus"},"workspace":{"current_dir":"'"$PWD"'"},"context_window":{"used_percentage":25,"context_window_size":200000}}' | src/statusline.sh
```

